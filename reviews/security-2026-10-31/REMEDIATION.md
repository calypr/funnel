# Security remediation

Work through the entire backlog. Verify each small complete fix, then continue. Record the simplest viable approach for findings that need broader design work and continue through the remaining findings.

## Workflow

1. Inspect every finding against the current source and assign a disposition.
2. For each small complete fix, add a focused behavioral regression, observe the baseline, apply the fix, and run the check again.
3. Record a concrete implementation plan for larger fixes and identify evidence gaps separately.
4. Review the combined changes and run affected package checks.
5. Finish only when every finding has an evidence-backed status and every retained fix has passed its focused checks.

The tracked backlog contains S01 through S19, P01 through P12, and D01, plus explicitly source-only observations. Verification uses synthetic local fixtures or recording transports. No deployed-service tests are implied.

All 32 numbered findings have a disposition. Twenty-two are fixed within their stated scope, nine larger fixes are deferred, and P09 has one fixed subfinding with the remaining ownership design deferred. S15 was reclassified and fixed after the user pointed out that direct log censorship did not require a redesign. Integration onto the security branch also retained and verified its existing rooted local-storage implementation for S03. Source observations and deployment evidence gaps are tracked separately below. This completes the small-fix backlog pass, not production security approval.

## Verification and compatibility

Run [remediation/verify.sh](remediation/verify.sh) against the working tree. It uses cached modules, local filesystem fixtures, recording transports and fake clients. The script excludes live databases, listeners, cloud operations, Docker execution and the historical audit probes. The latter intentionally reproduce defects in the frozen audited revision and are not remediation regression tests.

The current run selects the verified Go 1.27.3 binary through `FUNNEL_TEST_GO` and `GOTOOLCHAIN=local`. [Verification output](remediation/evidence/verification.txt) and the [fresh vulnerability scan](remediation/evidence/govulncheck.json) record actual results. The published scan retains every finding, scanner configuration/progress record, and advisory referenced by a finding; unrelated advisory descriptions are omitted. The full raw stream remains in the local transfer backup. The scanner was built from cached `golang.org/x/vuln@v1.9.0`, reports its build version as v0.0.0, and records go1.27.3 as the analyzed Go version. A nonfatal module stat-cache write warning appears during the build because the module cache is read-only; the build command exits zero.

Independent code review found and prompted fixes for copy-permission widening, missing shared-account fallback, and an unquoted role annotation. A fresh correction reviewer ran targeted tests and found no further defects in those corrections or provider binding checks. The comment review found no scoped issues. Historical baseline failures are recorded in this conversation; their raw output was not separately archived. The retained script/output verifies the final working tree.

The S15 follow-up uses direct field removal and fixed placeholders, with no new logging framework. Its production diff is [s15.patch](remediation/s15.patch), totaling 42 added and 59 removed lines across fourteen files. Six focused actual-output regressions cover application events, failed writes, RPC request/response logging, HTTP errors, plugin responses and plugin error formatting. [Before](remediation/evidence/s15-regression-before.txt) and [after](remediation/evidence/s15-regression-after.txt) outputs are archived for this follow-up. The independent three-leak check likewise records [before](remediation/evidence/s15-before.txt) and [after](remediation/evidence/s15-after.txt) results. Broader application logs now omit raw task stdout/stderr and free-form system-log details; owner-accessible task records are preserved. S07 and P03 remain deferred, with no scheduler permission or ServiceAccount selection changes in this follow-up.

OIDC deployments must now configure `RequireAudience`, and tokens must carry `exp`. HTTP gateway JSON requests must fit within 4 MiB, including JSON overhead. Local transfers consume disk/I/O for independent copies and respect source permission restrictions. Existing hardlinks, directories, ConfigMaps, Jobs and deployed containers are not migrated by source edits. AWS cancellation now requires `batch:TerminateJob` permission; cloud operation completion and retry/reconciliation remain deployment checks. Bundled Kubernetes template changes require workloads to use those updated templates.
